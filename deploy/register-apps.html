Register mesthiri's two GitHub Apps

Two Apps, so the stages that only read code cannot write it. Each button opens GitHub's App creation page with the name and permissions already filled in — you review and confirm. GitHub shows the private key once: save it before leaving that page.

On "no merge permission". GitHub has no separate merge permission to withhold — merging a pull request is authorised by contents: write, which the writer App needs in order to push a branch at all. So the writer App could merge, and mesthiri's guarantee that it never does rests on two things instead: branch protection on the target repository, and mesthiri having no code path that calls the merge endpoint. Keep branch protection on.

Afterwards

  1. Note each App's App ID and put them in the target repo's .mesthiri/config.scm as (apps (reader ID) (writer ID)). These are not secrets.
  2. Install both Apps on mesthiri/sandbox only, to start. An App's installation set is its blast radius.
  3. Add the private keys as repository secrets MESTHIRI_{"name": "mesthiri-reader", "url": "https://github.com/mesthiri/mesthiri", "description": "mesthiri: triage, prioritize, review and retro. Comments and labels; cannot write code.", "public": false, "default_permissions": {"issues": "write", "pull_requests": "write", "contents": "read", "metadata": "read"}, "default_events": ["issues", "issue_comment", "pull_request", "pull_request_review"]}_KEY and MESTHIRI_{"name": "mesthiri-writer", "url": "https://github.com/mesthiri/mesthiri", "description": "mesthiri: code and fix. Pushes branches and opens pull requests.", "public": false, "default_permissions": {"contents": "write", "pull_requests": "write", "issues": "write", "metadata": "read"}, "default_events": ["issues", "issue_comment", "pull_request"]}_KEY, then delete the downloaded .pem files.
  4. Verify with mesthiri whoami --app reader --key key.pem.
